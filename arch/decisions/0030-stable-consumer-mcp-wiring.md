# 0030 — Stable consumer-side MCP wiring: `.mcp.json` policy + `schema mcp-shim`

> **Y-statement** — In the context of ADR-0021 rotating the daemon
> bearer token on every restart (token lives in
> `~/Library/Application Support/schema/endpoint.toml` per
> ADR-0027's single-mount, single-token shape) and ADR-0019
> instructing consumers to wire Claude Code via a static
> `.mcp.json` carrying `url` + `Authorization: Bearer <token>`,
> facing the operational reality that **every daemon restart leaves
> every consumer's `.mcp.json` stale** (URL port and bearer rotate;
> Claude Code surfaces the failure as `ConnectionRefused` or `401`
> on next MCP request, observed in
> `/Users/farchanjo/.claude/debug/0f8782db-…txt` lines 117–140
> with the consumer pointing at `127.0.0.1:56612` while the daemon
> already moved to `127.0.0.1:57731`) and the runbook (`arch/
> operations/runbook.md` §4 lines 144–148) currently telling the
> operator to **re-run `schema mcp-config` and re-paste by hand**
> after every restart, facing the choice between (a) **`.mcp.json`
> versioned with literal token + URL** (operator-toil-heavy on
> every restart; bearer leaks into git history if committed; URL
> drift on port reuse), (b) **`.mcp.json` versioned with
> placeholders + post-clone substitution script** (still leaks if
> someone forgets, still requires per-restart toil), (c) **daemon
> rewrites every registered consumer's `.mcp.json` on startup**
> (daemon needs read-write filesystem access to every consumer
> tree it does not own; cross-project blast radius; violates
> ADR-0008 cache isolation by reaching outside `~/.cache/schema/
> projects/<id>/`; fragile under symlinks and worktrees), or
> (d) **`.mcp.json` is operator-local (gitignored), points at a
> long-lived `schema mcp-shim` stdio binary that re-reads
> `endpoint.toml` on connect and on `401`** (zero per-restart
> operator toil after first wiring; bearer never leaves the
> machine; URL drift absorbed by the shim; consumer side stays
> on the standard MCP stdio shape Claude Code already supports),
> we decided for **(d)**, against (a)/(b) (token leakage and
> per-restart toil are precisely what ADR-0021 §"Follow-up ADR:
> `schema mcp-shim` proxy" identified as worth promoting once
> friction surfaced — friction has now surfaced), and (c) (the
> daemon writing into consumer-tree files violates the
> single-direction information-flow ADR-0008 protects: consumers
> declare their corpus inward via `schema.toml`; the daemon
> writes outward only into `~/.cache/schema/`), to achieve
> **a `.mcp.json` shape that does not rot under daemon restart
> and does not require operator toil per session**, accepting
> **(1) one new binary subcommand (`schema mcp-shim`) implementing
> a stdio JSON-RPC bridge that proxies to the HTTP transport
> defined by ADR-0019 with bearer injection from
> `endpoint.toml`, (2) `.mcp.json` becoming gitignored and
> regenerated by `schema mcp-config --shim` for first-time
> wiring, (3) a 24-hour grace window where the legacy direct-URL
> `.mcp.json` shape (ADR-0019 §"Shape A") still works
> unchanged, and (4) the runbook is rewritten so the canonical
> step is `schema mcp-config --shim > .mcp.json` once, never
> re-run unless `endpoint.toml` location changes**.

## Context and Problem Statement

ADR-0021 documented the bearer-rotation behaviour and explicitly
flagged a follow-up:

> **Follow-up ADR:** `schema mcp-shim` proxy (Shape B). Promote
> to a real ADR once Shape A's friction is observed in practice.

Shape A friction is now observable. From the user's debug capture
(`/Users/farchanjo/.claude/debug/0f8782db-…txt`):

```
2026-04-27T12:34:21.270Z [DEBUG] MCP server "schema":
  HTTP Connection failed after 6ms: Unable to connect.
  Is the computer able to access the url?
  (code: ConnectionRefused, errno: none)
2026-04-27T12:34:21.270Z [ERROR] MCP server "schema"
  Connection failed: Unable to connect.
  Is the computer able to access the url?
```

The consumer's `.mcp.json` pointed at `127.0.0.1:56612` with token
`5458935c-…`; the daemon was bound to `127.0.0.1:57731` with token
`6c3532ba-…` (per `~/Library/Application Support/schema/endpoint.
toml`). Both URL and token rotated on the last restart. The
session was wedged until `schema mcp-config` was re-run by hand
and the output pasted in.

The cost compounds: every operator with `schema` registered as an
MCP server pays this toll on every daemon restart. Daemon
restarts happen on macOS reboot, on `launchctl kickstart -k`, on
crash + KeepAlive recovery, and on every `schema install` or
`schema uninstall` cycle.

`.mcp.json` is also currently **untracked but unignored** in this
repo (`?? .mcp.json` in `git status`). There is no policy
written down anywhere about whether it belongs in git, whether
it ships as a template, or whether it is a per-machine artefact.
Today's de-facto behaviour is "operator forgets to gitignore it,
it eventually gets committed with a token, token rotates within
hours, dead artifact ships forever in git history".

## Decision drivers

- **Restart resilience.** The operator should not need to touch
  `.mcp.json` between MCP sessions even when the daemon restarts.
- **Token containment.** The bearer should not be reachable
  outside the daemon's user account. Plain-text in committed
  `.mcp.json` violates this even if rotation makes the leak
  short-lived.
- **Filesystem-isolation symmetry with ADR-0008.** Consumers
  declare inward via `schema.toml`. The daemon writes outward
  only into `~/.cache/schema/projects/<id>/` and (per
  ADR-0027) `~/Library/Application Support/schema/endpoint.toml`.
  No new direction.
- **Claude Code support shape.** Claude Code's `.mcp.json`
  natively supports both `"type": "http"` (Shape A) and
  `"type": "stdio"` (binary + args). A stdio shim slots in
  without changing the consumer surface.
- **Backwards compatibility.** Existing consumer `.mcp.json`
  files using Shape A continue to work as long as the operator
  re-pastes after a restart. Shape A is not removed; Shape B
  is added and recommended.

## Considered options

### Option (a) — Versioned `.mcp.json` with literal URL + token
- Token leaks into git on the first commit.
- URL is unstable across restarts even on the same machine.
- Per-restart toil unchanged.
- **Rejected** — same friction this ADR exists to remove.

### Option (b) — Versioned `.mcp.json` with placeholders + substitution script
- Reduces commit-time leakage if the script is the only writer
  (still error-prone — `git commit` after a manual edit will
  carry the live token).
- Per-restart toil unchanged: the script must run on every
  daemon restart.
- Adds a second build artefact (the script) without removing
  the underlying problem.
- **Rejected** — does not solve restart drift.

### Option (c) — Daemon rewrites each registered consumer's `.mcp.json`
- Daemon needs r/w access to every consumer-tree path it
  does not own.
- Cross-project blast radius: a buggy daemon write could
  corrupt unrelated consumer files.
- Violates ADR-0008's information-flow direction (daemon
  writes outward only into its own cache; consumers write
  outward only into their own corpus).
- Symlinks, worktrees, multi-machine syncs amplify the
  failure surface.
- **Rejected** — security and isolation cost too high.

### Option (d) — `.mcp.json` is operator-local + `schema mcp-shim` stdio bridge
- Consumer's `.mcp.json` declares a stdio MCP server pointing
  at `schema mcp-shim`.
- Shim runs as a child process per Claude Code session, reads
  `~/Library/Application Support/schema/endpoint.toml`
  on startup, opens the HTTP MCP connection per ADR-0019, and
  bridges Claude Code's stdio JSON-RPC frames to the HTTP
  transport.
- On `401` from the daemon, shim re-reads `endpoint.toml`
  (token rotated) and retries once before propagating the
  error.
- On `ECONNREFUSED` from the daemon, shim re-reads
  `endpoint.toml` (URL rotated) and retries once.
- `.mcp.json` shape becomes:

  ```json
  {
    "mcpServers": {
      "schema": {
        "type": "stdio",
        "command": "/usr/local/bin/schema",
        "args": ["mcp-shim"]
      }
    }
  }
  ```

- No URL, no token, no rotation surface in the consumer file.
- `.mcp.json` is gitignored. First-time wiring is one command:
  `schema mcp-config --shim > .mcp.json`.
- **Selected.**

## Decision

We adopt **option (d)**.

1. **Implement `schema mcp-shim`** as a new subcommand on the
   `schema` binary. Single binary, no new dependency. Reads
   `~/Library/Application Support/schema/endpoint.toml`
   (path resolved per ADR-0027 — single global file post the
   2026-04-27 cutover); opens the HTTP MCP connection per
   ADR-0019; bridges stdio ↔ HTTP. Re-reads `endpoint.toml`
   on `401` and on `ECONNREFUSED` exactly once before
   surfacing the error. Logs to `stderr` only (Claude Code's
   stdio transport already isolates stderr from the
   JSON-RPC channel).

2. **Extend `schema mcp-config`** with a `--shim` flag emitting
   the stdio shape (binary + args), defaulting to the absolute
   `/usr/local/bin/schema` path resolved at config-emission
   time (ADR-0014 install location).

3. **Gitignore `.mcp.json`** in this repo. Consumer trees
   adopting `schema` as an MCP server should also gitignore
   their `.mcp.json` — the runbook will call this out.

4. **Rewrite `arch/operations/runbook.md` §4** to make the
   `--shim` shape the canonical wiring. Shape A (direct URL +
   token) stays documented as the legacy/debug path with an
   explicit "regenerate after every restart" warning.

5. **`endpoint.toml` schema does not change.** The shim is a
   pure consumer of the existing `version = 1`
   `(url, token, pid, started_at)` shape pinned by ADR-0021.

6. **No daemon-side changes.** The HTTP transport (ADR-0019)
   and bearer-auth middleware (ADR-0021 §"validator shape
   reverted by ADR-0027") are unchanged.

## Consequences

- **Good:** zero per-restart operator toil. After
  `schema mcp-config --shim > .mcp.json` once per consumer
  tree, the wiring survives daemon restarts indefinitely.
- **Good:** `.mcp.json` no longer carries secrets. Even if it
  is accidentally committed, the leak is the path to the
  shim binary, not a bearer token.
- **Good:** consistent with ADR-0008 isolation — daemon owns
  `~/.cache/schema/` and `~/Library/Application Support/
  schema/`; consumers own their tree; nobody writes across
  the boundary.
- **Good:** the shim is a thin process per session; cost is
  one extra fork per Claude Code MCP connection (already
  the cost shape for any stdio MCP server).
- **Neutral:** Claude Code's HTTP MCP transport stays
  supported (ADR-0019 unchanged). Operators who prefer the
  direct shape can keep it; they will re-paste manually.
- **Bad:** one more subcommand on the `schema` binary
  (`mcp-shim`). Modest binary-size impact.
- **Bad:** the shim is now a load-bearing piece of the
  consumer wiring path. Bugs in the shim (token-rotation
  race, EOF handling on shutdown, stdio backpressure) are
  surfaced as Claude Code MCP failures. Mitigations:
  unit tests on bridge framing; integration test that
  rotates the token mid-session and asserts recovery.
- **Bad:** the shim depends on `endpoint.toml` being readable
  by the operator's UID. ADR-0021 already mandates `0600`
  with the operator as owner; cross-account daemon shares
  remain out of scope (would need a new ADR).

## Fitness function

- **Unit test (shim framing):** stdio bridge round-trips one
  `initialize` request, one `tools/list` request, one
  `tools/call` request. JSON-RPC framing is byte-exact in
  both directions. Tests live in
  `src/cli/mcp_shim.rs#[cfg(test)]` against an
  `axum_test::TestServer` mounting the real
  `build_router` from ADR-0019.
- **Integration test (token rotation recovery):** start
  daemon → wire consumer via `schema mcp-shim` → issue one
  authenticated `tools/list` → restart daemon
  (`endpoint.toml` rotates `token` and `pid`) → issue
  second `tools/list` from the same shim instance →
  assert success on the second call without manual
  intervention. Lives in
  `tests/integration/mcp_shim_rotation.rs`.
- **Integration test (URL rotation recovery):** same shape
  but force the daemon to bind a different port on
  restart (compose stop/start with `port = 0` randomisation
  in `schema.toml`). Assert the shim picks up the new URL
  from `endpoint.toml` on `ECONNREFUSED` retry. Lives in
  `tests/integration/mcp_shim_rotation.rs`.
- **Lint (no `.mcp.json` in git):** CI grep gate —
  `git ls-files | grep -E '^\\.mcp\\.json$' && exit 1 || true`.
  Optional, low-cost guard. The gitignore entry is the
  primary defence.
- **Doc lint (runbook canonical shape):** `arch/operations/
  runbook.md` §4 contains the `schema mcp-config --shim`
  invocation as the **first** wiring path; Shape A is
  marked `legacy / per-restart`.

- **ADR-0021 — Localhost bearer auth.** §"Follow-up ADR:
  `schema mcp-shim` proxy (Shape B)" is closed by this ADR.
  An `Evidence and amendments` entry on ADR-0021 will
  link here on accept.

  global `endpoint.toml` location is a precondition; the
  shim reads exactly that path.

  this ADR's implementation, not a separate follow-up.
- **Follow-up:** consider a long-running `schema mcp-shim

  restarts and multiplexes connections. Defer until at
  least one operator reports per-session-fork latency
  pain.
- **Follow-up:** Linux `~/.config/schema/endpoint.toml`
  path resolution (XDG) — covered by ADR-0027's Linux
  amendment if/when the macOS-only path becomes a
  cross-platform concern.
